The published file never contains exact Dependabot alert counts (see README.md); for exact counts, sign in and check a repository's own GitHub Security tab.             These coverage gaps mean a signal could not be verified, or a security feature is turned off. "Could not be read" is usually a missing permission on the scan token (below). Neither is evidence that a repository is insecure or non-compliant.

            How to set up the scan token (MAINTENANCE_RO_TOKEN)
            1. Create a fine-grained personal access token at GitHub → Settings → Developer settings → Fine-grained tokens.
            2. Resource owner: the account being scanned. Repository access: All repositories (only public ones are ever scanned).
            3. Repository permissions, all Read-only: Dependabot alerts, Administration (for security settings and classic branch protection). Metadata is added automatically. Nothing else, and nothing with write access.
            4. Set an expiry, and a reminder to renew it.
            5. In the repository running this dashboard: Settings → Secrets and variables → Actions → New repository secret, named MAINTENANCE_RO_TOKEN.
            6. The next scheduled scan uses it. Gaps that remain "could not be read" name the permission still missing.
